name: setup
description: Set up the companion with a person's own environment key, approve its project MCP server and run the read-only doctor, with Chrome-only setup for members without personal keys.
---
## Task
Help the person connect safely and confirm what actually works. Never ask for, view or handle the key.

## Method
For every step a listed, permitted tool is preferred. Setup has no MCP tool for key creation or environment changes. Use the named manual or Chrome path below. If any tool is refused, explain it, offer the relevant Chrome path and wait for yes. A failed step stops, is said aloud in plain English and follows `guides/recording.md` when an accessible task exists. If connection failure prevents recording, explicitly say the result is not recorded and offer the safe note text for the person. Do not create a loop by retrying setup to record setup.

1. Read `CLAUDE.md` and the README. Check the person opened the cloned companion folder. If they say the variable is already added, or they are returning after a restart, run the doctor in step 5 first. When the key is present and the connection works, skip key creation, entry and another restart. Never ask them to replace a working key. Otherwise ask whether they are an admin creating their own key or a member. Never accept another person's admin key. A member uses Chrome only until Nurture offers personal keys. In Chrome open `/tasks` and confirm their own account and workspace visually, without exposing account settings or credentials. If Chrome is not connected, ask the person to install and sign in to the Claude in Chrome extension themselves; then reconnect. Never make an authenticated Nurture shell call to replace Chrome.
2. An admin creates a key themselves in Nurture `/developers`, **API keys**, **Create key**, **Name** set to their own name, **Permissions**, and optional **Expiry (optional)**, then **Create key**. Explain only the needed task/document tool permissions from this kit; do not request unrelated permissions. Pause browser and desktop control before they open the one-time key display. No MCP tool creates a personal key today. Members without this screen keep using Chrome; they must not borrow credentials or gain an admin role as a workaround.
3. Tell the person to enter the key outside chat. On Windows: **Start**, type **environment variables**, select **Edit environment variables for your account**, **New** under user variables, name `NURTURE_API_KEY`, value entered by the person, save. In Claude Desktop, use Code's environment settings instead if present. On Mac use those app settings if available; otherwise the person enters a profile export line in their own editor outside this repo, never a Terminal command containing the value. Explain that Finder-launched apps may not inherit shell profiles. Follow the README's launch guidance or ask IT. Do not inspect or edit the profile. Do not use desktop control, screenshots or clipboard tools on any key-entry screen. The person alone performs this native step.
4. Ask the person to fully quit and restart Claude Code, reopen this folder, and approve the project MCP server **nurture** when prompted. Pause until they return. `.mcp.json` is the only registration path. Do not change configuration, add another server or weaken permissions. A member without a key will see a "missing environment variable" notice for the **nurture** server. This is expected until personal keys arrive. Continue with Chrome only; do not enter a placeholder or borrow someone else's key. The doctor will name the missing connection.
5. Run exactly `bash scripts/doctor.sh`. It checks OS, Git, readable Claude Code version, checkout, protected folders, key presence and one `tools/call` of `list_tasks` with `limit: 1`. The version is information only; no known minimum version is claimed for the remaining settings. Explain each **MISSING** fix and each **UNKNOWN**, without inspecting the environment or the response body. **OK Nurture key: accepted** means this task read worked. A 401 means **MISSING Nurture key: refused, create a new one in Nurture**. A 403 means **MISSING Nurture key: works but lacks task permission; ask your admin to add list tasks**. For a tool refusal, explain that a listed tool can still lack permission. Offer the signed-in Chrome page for the requested job and wait for yes; never silently retry through Chrome.
6. If everything relevant is OK, use `my-tasks` for one requested read. Browser-only members use `/tasks`, **My tasks**. Confirm any result note before writing it. Do not claim the doctor proves every task permission or browser action works. Record setup outcome on the agreed task using `comment_on_task` when permitted, otherwise `/tasks`, **Notes**, **Add a note**, **Add note**, under `guides/recording.md`.
7. Explain that the startup hook runs only at a new session start, uses `bash scripts/update.sh`, and keeps `my-notes/` and `downloads/`. If it reports **Companion updated: restart Claude Code to apply**, ask for a restart and wait. If it says **Companion update skipped**, explain that reason and use cached instructions only after saying they could be older. The updater reclaims empty locks older than two minutes. Do not manually remove a lock or edit the kit to repair updates; ask the administrator if failures continue.

## Requirements
Own Claude account, Claude Code desktop app, Git, Windows Git Bash or macOS, Claude in Chrome and a suitable plan. Chrome needs Pro, Max, Team or Enterprise; native desktop control needs Pro or Max. No scripts write or print the key. No package manager, Node or Python is required.

## Reference files
`CLAUDE.md`; `README.md`; `.mcp.json`; `scripts/doctor.sh`; `scripts/update.sh`; `guides/recording.md`.

## Result
State tool connection, Chrome availability, any unknown version or missing requirement, and whether setup was recorded. Chrome-only operation is limited to screens the person can already access.

## Tools and integrations
Local: `bash scripts/doctor.sh`, `bash scripts/update.sh`. Nurture MCP: `comment_on_task` for confirmed recording. Chrome: `https://app.nurtureoutreach.com/developers` and `/tasks`. Native settings and key entry are performed by the person with control paused.
